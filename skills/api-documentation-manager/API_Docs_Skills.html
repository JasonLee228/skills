📘 Cursor Skill

API Documentation Manager 스킬
사용 가이드

백엔드 API 소스코드를 분석하여 Docusaurus 기반 API 명세 문서를 신규 작성하거나, 기존 문서를 업데이트·리팩토링하는 Cursor 스킬입니다. Spring, Node.js 등 다양한 백엔드 프레임워크를 지원합니다.

🔍 소스코드 전체 분석 📄 Docusaurus 기반 문서 🌿 Spring / 기타 백엔드 🔄 업데이트 / 리팩토링 🔗 객체 참조 문서 ⚠️ 전체 오류 케이스 포함
1
스킬이란?

Cursor 스킬은 AI 에이전트가 특정 작업을 수행할 때 참고하는 지침 모음입니다. 이 스킬은 신규 API 문서 작성뿐 아니라 기존 문서 업데이트·리팩토링까지 모두 지원합니다.

📝
"이 컨트롤러 API 명세서 작성해줘" — 신규 작성
소스코드를 Service·Repository 레이어까지 전체 추적하여 요청/응답 필드, 오류 케이스를 모두 포함한 Docusaurus 문서를 생성합니다.
🔄
"API 문서 업데이트해줘" — 소스코드 변경 반영
현재 소스코드와 기존 문서를 비교하여 변경된 필드·오류 코드·권한 등을 사용자에게 보고한 후 선택적으로 반영합니다.
🛠
"API 문서 리팩토링해줘" — 문서 구조 개선
중복 오류 코드 분리, 파일명 정규화, 누락 항목 추가, 객체 참조 문서 생성 등 소스코드 변경 없이 문서 품질을 개선합니다.

사용 방법
⚡ 트리거 문구
아래 문구 중 하나를 입력하면 스킬이 동작합니다.
신규 작성
📝 API 명세서 작성해줘 📘 API 문서 만들어줘 이 컨트롤러 문서화해줘 API 스펙 문서 생성해줘
업데이트 / 리팩토링
🔄 API 문서 업데이트해줘 🛠 API 문서 리팩토링해줘 API 문서 최신화해줘
💡 대상 API 위치를 함께 명시하면 더 빠르게 진행됩니다. 예: "UserController.java API 명세서 작성해줘"
🔄 전체 사용 흐름
🔵 사용자 입력 🟢 AI 자동 처리 🟡 조건부 (필요 시 확인)
1
대상 API 위치 입력 사용자 입력
문서화할 API의 위치를 알려주세요.
  • 폴더: src/main/java/com/example/controller/
  • 파일: UserController.java
  • 특정 API: UserController의 POST /users
2
문서 저장 위치 입력 사용자 입력
API 명세 문서를 저장할 부모 폴더 경로를 입력합니다.
  • 예: docs/api, website/docs/api-specs
3
소스코드 전체 분석 자동
컨트롤러 → Service → Repository 레이어까지 전체 로직을 추적합니다.
  • HTTP 메서드, URL, Path Variables, Query Parameters, Body 분석
  • 권한(Authority) 정보, Request Headers 파악
  • Response 객체 필드 분석
  • 모든 예외 처리 케이스 추적 (GlobalExceptionHandler 포함)
4
불명확한 사항 확인 필요 시 질문
분석 중 명확하지 않은 오류 코드 의미, 비즈니스 규칙 등이 있다면 사용자에게 확인합니다.
5
문서 저장 위치 및 구조 결정 자동
부모 폴더 내 기존 도메인 폴더를 확인하고 구조를 결정합니다.
  • 기존 도메인 폴더 번호 확인 → 신규 시 다음 번호로 폴더 생성
  • 신규 폴더 생성 시 _category_.json 자동 작성
  • 중복 항목 발견 시 객체 참조 문서 생성 여부 결정
6
Docusaurus 문서 작성 자동
분석 결과를 바탕으로 형식에 맞는 API 명세 문서를 작성합니다.
  • Front Matter (sidebar_position, title, tags)
  • Request (URL, Headers, Authority, Path Variables, Query Params, Body)
  • Response (HTTP Status, Body 전체 필드)
  • Error Cases (발생 가능한 모든 오류 케이스)
  • Example (Request/Response 예시)
7
검토 및 최종 확정
생성된 문서를 검토하고, 누락된 오류 케이스나 필드가 있으면 보완합니다.
🔄 업데이트 / 리팩토링 흐름
🔄 업데이트
API 소스코드가 변경되어 기존 문서를 최신화

소스코드와 기존 문서를 비교하여 변경된 항목만 사용자에게 보고 후 반영
🛠 리팩토링
소스코드 변경 없이 문서 구조·중복·내용을 개선

중복 오류 코드 분리, 파일명 정규화, 누락 항목 추가 등
U1
기존 문서 + 소스코드 위치 입력 사용자 입력
기존 문서 경로와 대응하는 소스코드 경로를 입력받습니다. (리팩토링은 소스코드 선택 사항)
U2
기존 문서 전체 읽기 자동
대상 문서(단건 또는 폴더 전체)와 참조 문서를 읽어 현재 상태를 파악합니다.
U3
소스코드 비교 또는 문서 검토 자동
업데이트: 소스코드와 기존 문서를 비교해 변경 항목을 도출합니다.
리팩토링: 구조·중복·누락 등 개선 항목을 파악합니다.
U4
변경/개선 항목 사용자 보고 후 확인 사용자 확인
변경/개선 사항을 요약하여 보고하고, 사용자 확인을 받은 항목만 반영합니다.
U5
문서 수정 및 최종 검토 자동
파일 전체를 덮어쓰지 않고 변경된 섹션만 수정합니다. 참조 문서 분리 시 링크를 자동으로 교체합니다.

# SSL 인증서 등록
### 해당 회사에서 사용할 SSL 인증서를 등록한다.
## Request
### URL
> POST /api/ssl-certifications
### Body
| NAME | TYPE | REQUIRE | DESCRIPTION |
| companyId | UUID (String) | TRUE | 회사 아이디 |
| certificatePem | String | TRUE | PEM 형식 인증서 |
## Error Cases
| HTTP Status | Error Code | Error Message |
| 400 | C4001 | 유효하지 않은 PEM 형식 |
| 403 | C4005 | MASTER 또는 ADMIN 권한 없음 |
... 전체 오류 케이스 포함 ...

• 예: 29. ScreenMark

• 예: 00. ScreenMark.md
• 예: 01. CreateScreenMark.md

📋 _category_.json 자동 생성

신규 도메인 폴더 생성 시 항상 _category_.json을 함께 작성합니다. position은 폴더 번호와 동일하게 설정합니다.

{
  "label": "📁 SSL 인증서",
  "position": 30, // 폴더 번호와 동일
  "link": {
    "type": "generated-index",
    "description": "SSL 인증서 등록, 수정, 삭제 API"
  }
}

주의사항
🔍
소스코드 접근 가능 환경 필요
AI가 소스코드를 직접 읽어 분석합니다. Cursor에서 해당 프로젝트가 열려 있어야 하며, 대상 파일/폴더 경로가 정확해야 합니다.
⚠️
오류 코드/메시지 확인 필요
커스텀 예외 클래스나 오류 코드 상수가 별도 파일에 정의된 경우, AI가 자동으로 찾아 분석합니다. 그러나 오류 메시지의 비즈니스 의미가 불명확하면 직접 확인을 요청합니다.
📁
Docusaurus 프로젝트 기반 경로 지정 권장
문서 저장 위치는 실제 Docusaurus 프로젝트의 docs/ 하위 경로를 지정해야 사이드바에 올바르게 표시됩니다. 경로가 맞는지 확인 후 지정하세요.
🔄
기존 문서 리팩토링 시 중복 확인
기존 도메인 폴더에 문서를 추가할 때, 공통 응답 구조나 오류 코드가 이미 참조 문서로 분리되어 있다면 해당 참조 문서를 활용합니다. 새로 중복 내용을 추가하지 않도록 주의하세요.
🔁
스킬 설치 후 Cursor 재시작 필수
스킬을 새로 설치한 경우 Cursor를 한 번 완전히 종료 후 다시 실행해야 인식됩니다.
6
문제 해결
증상 확인 사항
스킬이 동작하지 않음 skills 경로가 맞는지, api-documentation-manager 폴더 전체가 복사되었는지 확인
AI가 질문하지 않음 Cursor 재시작 후 새 채팅에서 다시 시도
소스코드를 찾지 못함 대상 파일/폴더의 정확한 경로를 다시 입력. 프로젝트가 Cursor에 열려 있는지 확인
오류 케이스가 누락됨 GlobalExceptionHandler 또는 커스텀 예외 클래스 파일 경로를 AI에게 추가로 알려주면 재분석 가능
문서 형식이 다름 api-docs-format.md 내용을 팀 규칙에 맞게 수정하거나, AI에게 원하는 형식을 직접 알려주세요
폴더 번호가 잘못됨 부모 폴더 내 기존 폴더 목록을 AI에게 다시 알려주면 올바른 번호로 재생성 가능. 폴더는 {숫자}. {PascalCase}, 파일은 {NN}. {PascalCase}.md 형식 사용
업데이트 시 변경 사항을 못 찾음 기존 문서 경로와 소스코드 경로를 정확하게 다시 입력. 두 파일 모두 Cursor에서 접근 가능한지 확인
리팩토링 후 참조 링크가 깨짐 참조 문서의 실제 경로와 링크의 상대 경로가 일치하는지 확인. AI에게 경로 재검토 요청
