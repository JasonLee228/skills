# 검증과 리뷰

변경된 계약과 위험에 맞는 최소 충분한 증거를 확보한다. 실행하지 않은 검사, 과거 결과, 환경 오류를 현재 PASS로 합치지 않는다.

## 검증 선택

프로젝트의 실제 명령과 환경을 사용한다. 특정 IDE 도구가 없다는 이유로 검증을 생략하거나 도구 이름만 PASS로 기록하지 않는다.

| 변경 | 주요 확인 |
|---|---|
| 문서·주석·단순 설정 | diff, 링크/구문, 실제 설정 의미에 맞는 확인 |
| 서비스·DTO 변환 | 정상·실패·경계 계약의 관련 테스트 |
| API·권한 | request/response/error, 권한·테넌트 경계, 명세 대조 |
| Repository·DB migration | 실제 query/schema 적용, 기본값·호환성, rollback 또는 복구 제약 |
| 비동기·스케줄·메시징 | 활성/비활성, 중복 실행, 실패·재시도, 멱등성·동시성 |
| 외부 연동·대량 처리 | timeout, 부분 실패, limit/chunk, 영향받는 회귀 |
| 운영 변경 | 배포 순서·기본값·관측·복구 조건, 실제 운영 검증의 수행 여부 |

기능·버그 변경은 가능한 한 실패 케이스를 먼저 확인하고 구현 후 통과시킨다. 테스트 편의를 위해 프로덕션 가시성·계약을 넓히지 않는다. 프로젝트에 테스트 가능성 규칙이 있으면 그 기준을 적용한다.

## 유효한 실행 증거

검증 행에는 시각, 실제 명령/확인 항목, 결과, 핵심 로그 또는 근거 위치를 남긴다. 공유하는 환경 정보는 실행 묶음에 한 번만 적는다.

- 작업 경로, branch/기준 커밋과 검증한 변경 범위. dirty 작업은 HEAD만으로 식별하지 않는다.
- 관련 writer의 쓰기 종료와 실행 주체. 위임한 경우 재확인 가능한 반환 결과/로그.
- PASS/FAIL/미실행, 필요한 테스트 수·exit code·핵심 실패 원인.
- 미실행 사유·대체 검증·남은 위험.

[위임 가이드](subagent-delegation-guide.md)의 공유 자원과 쓰기 종료 기준을 적용한다. 이전 결과를 재사용하려면 이후 관련 코드·테스트·설정/환경이 바뀌지 않았는지 확인한다. 바뀌었다면 영향받는 검증을 다시 수행한다. 사용자 요청 또는 의심 근거가 있으면 fresh 실행을 우선한다.

생성 코드·증분 class·오래된 보고서 때문에 결과가 의심되면 그 산출물의 최신성을 확인하고 필요한 clean/recompile을 수행한다. 공유 작업자의 빌드 출력은 임의로 삭제하지 않는다.

## 실패와 검증 한계

기능 assertion 실패와 환경/의존 서비스 오류를 구분한다. 환경 오류라는 이유로 해당 테스트를 PASS로 표시하지 않는다. 실행했다가 실패한 검사는 FAIL이며, 실행하지 않은 검사만 미실행이다.

전체 검증이 막혀 집중 테스트만 통과했다면 각각의 범위와 결과를 별도로 기록한다. 미완료 필수 검증은 완료 판단의 제한으로 남긴다. 코드 수정 없이 이미 유효한 증거가 있으면 같은 검사를 반복하는 대신 근거를 연결한다.

## 코드 리뷰

구현된 diff와 영향받는 호출 계약을 보안, 정확성, 성능, 테스트, 유지보수 관점에서 검토한다. 프로젝트의 리뷰 스킬이나 체크리스트가 있으면 적용하며, 부재하면 이 기준으로 직접 검토하고 대체 검토 사실을 짧게 남긴다.

주석·문서 코멘트·논리적 빈 줄도 확인한다. 프로젝트의 주석 규칙을 사용하고, 없으면 공개 계약·단위·실패 조건과 주석의 일치, 낡거나 중복된 설명, 읽기 흐름을 직접 확인한다. 도구/규칙 파일 부재만으로 중단하지 않는다. 계약이 불명확하거나 필수 증거가 부족하면 그 한계를 기록한다.

코드와 주석 검토는 같은 리뷰어·회차에서 수행할 수 있으며 결과에서 구분한다. 별도 Agent나 문서는 독립 검토 또는 전문성이 필요한 경우에 사용한다. 사용자나 프로젝트가 별도 리뷰를 요구하면 그 기준을 따른다. 위임 구현·고위험 변경은 구현에 참여하지 않은 리뷰어의 검토를 우선한다.

리뷰 결과에는 대상 범위·검토자/기준·finding·반영 또는 보류 이유·검증 한계를 남긴다. finding이 없으면 0건과 범위를 기록한다. 기존 전체 변경 리뷰가 현재 diff에도 유효하면 재사용하고, 수정 후에는 영향받은 finding과 범위를 재검토한다. Task마다 같은 전체 리뷰를 반복하지 않는다.

Critical은 해당 결과의 수용을 막는다. 수정·재승인 여부는 [workflow의 변경 판단](workflow-guide.md#4-중단과-재승인)을 따르며 심각도와 사용자 결정 필요성을 혼동하지 않는다.
