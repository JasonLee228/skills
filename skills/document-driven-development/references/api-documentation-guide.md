# API 명세 반영

신규 API 또는 기존 request/response/error/권한·동작 의미가 바뀌면 명세 반영을 준비한다. 상태 코드, pagination·정렬·필터 등 소비자가 의존하는 변경도 포함한다.

## 설계 시

plan에 변경되는 method/path 또는 공개 계약, 기존 명세 위치, 신규/수정 여부를 남긴다. 위치는 프로젝트 규칙과 실제 문서에서 확인한다. Docmost·Confluence 등 특정 제품·폴더 경로를 다른 프로젝트에 그대로 적용하지 않는다.

API 변경이 없다면 impl 후속 결과에 한 줄로 판단을 남기면 된다.

## 구현 후

1. 실제 코드의 request/response/error/권한·기본값과 예시를 명세에 대조한다.
2. [외부 쓰기 기준](workflow-guide.md#6-외부-업데이트)에 따라 승인과 인증을 확인하고 반영한다.
3. 쓰기 후 대상 문서를 재조회해 의도한 변경을 확인한다. 기존 내용은 필요한 범위만 수정한다.
4. impl 후속 결과에 문서 링크와 반영 근거, 또는 승인 대기/실패 사유·준비한 반영 내용을 기록한다.

구현이 승인 설계와 다르면 먼저 [변경 판단](workflow-guide.md#4-중단과-재승인)을 거친다. 명세를 바꿔 미승인 계약 변경을 정당화하지 않는다. 명세 승인 대기를 API 문서 완료로 보고하지 않는다.
