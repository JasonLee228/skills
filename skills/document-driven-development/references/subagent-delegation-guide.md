# SubAgent 위임과 통합

구현·조사·검증·리뷰를 위임할 때 읽는다. 부모는 범위, 문서, 결과 수용, 통합 증거, stage와 외부 업데이트의 최종 책임을 가진다. 실행 주체와 병렬화는 따로 정한다.

## 실행 방식 선택

| 판단 | 기준 |
|---|---|
| 직접 수행 또는 위임 | 사용자 지시, 작업 크기, 전문성·컨텍스트 분리 이점과 전달 비용. 단일 TODO도 한 Agent에게 순차 위임 가능 |
| 결합된 구현·테스트 | 같은 담당자가 묶어서 수행 가능. 결합 자체는 위임 금지 사유가 아님 |
| 병렬 실행 | 실행할 계약이 확정되고 의존 결과가 준비됐으며, 쓰기 경로와 공유 자원 충돌이 없을 때 |
| 같은 파일·미해결 의존성 | 하나의 담당자에게 묶거나 선행 결과를 수용한 후 순차 인계 |
| 조사·리뷰 | 안정된 읽기 대상과 독립 질문이면 병렬 가능. 미확정 설계의 조사도 가능하지만 코드 구현은 승인 후 |
| 테스트 작성과 실행 | 확정된 계약으로 테스트 작성은 별도 경로에서 병렬 가능. 통합 실행은 필요한 구현과 테스트가 모인 후 |

위임을 매 작업에 강제하지 않는다. 사용할 수 있는 동시 실행 수와 실행 환경 제약을 따른다. 모델·외부 runner는 사용자 지정과 해당 도구/스킬 기준을 사용하며, 실행 세부 설정을 DDD 문서마다 복제하지 않는다.

## 소유권과 전달

impl의 기존 TODO 표에 위임할 때만 담당·쓰기 경로·선행 TODO·공유 자원을 추가한다. 별도 진행 장부는 만들지 않는다. 한 시점의 파일 소유자는 한 명이며, 하위 Agent는 DDD·공통 진행 문서와 Git index를 수정하지 않는다.

위임 brief는 다음 순서로 전달한다.

1. 작업 경로·기준 상태, 관련 plan/impl 경로와 필요한 섹션.
2. 담당 TODO, 입력 계약·완료 조건·선행 결과.
3. 허용 쓰기 경로와 제외 범위, 공유 빌드/테스트/생성 산출물의 실행 담당.
4. 실행할 검증과 반환할 결과. DDD 수정·stage·commit·push·승인되지 않은 외부 쓰기 금지.

전체 대화나 문서를 복사하지 않는다. 범위 밖 파일·계약 변경이 필요하면 그 부분을 멈추고 부모에게 보고한다. 부모가 명시적으로 위임하지 않은 외부 업데이트는 수행하지 않는다.

## 공유 작업 트리와 검증 시점

소스 파일이 달라도 빌드 출력(`target/`, `build/`, `dist/`), 생성 코드, 테스트 보고서, 같은 테스트 DB/포트는 공유될 수 있다. 검증 작업은 소스에 읽기 전용이어도 산출물을 쓴다. 공유 출력에는 실행 담당을 한 명 두거나 실제로 격리된 경로/환경을 사용한다. 같은 checkout의 `clean`·빌드·테스트·생성 산출물 갱신을 서로 충돌하게 실행하지 않는다.

통합 검증·최종 리뷰·stage 전에 해당 결과에 영향을 주는 작업자의 쓰기가 모두 끝났는지 확인한다. 이 안정된 변경 범위에 대해 검증한다. 결과가 나온 뒤 관련 변경이 추가되면 그 영향을 받은 검증·리뷰만 다시 수행한다. 무관한 독립 작업까지 전부 멈출 필요는 없다.

공유 트리에서는 worker의 변경이 이미 디스크에 있다. 결과 거부는 자동 rollback을 뜻하지 않는다. 부모가 diff와 소유권을 확인하고 해당 작업자에게 범위 내 수정을 맡기거나 안전하게 인계한다. 사용자·다른 작업자의 변경을 되돌리지 않는다.

## 결과 반환과 수용

worker는 작업 완료/실패/중단 상태, 실제 변경 파일·내용, 검증 명령·결과·근거, 미실행 항목과 사유, 계약 차이·위험을 반환한다. 실행 식별자나 로그가 있으면 재확인 가능한 위치도 전달한다.

impl TODO 상태는 `대기 → 작업 중 → 검토 대기 → 수용 완료`로 구분한다. 막히면 차단 사유와 다음 행동을 붙인다. worker의 DONE은 검토 대기이며 부모만 수용 완료로 바꾼다. 기존 체크박스를 쓰는 작업은 수용 완료에서만 체크한다.

부모는 다음을 확인한다.

1. 실제 diff·쓰기 경로·기존 변경 보존과 승인 계약 충족.
2. 실행 종료 상태와 실제 증거. exit 0이나 최종 메시지만으로 PASS를 인정하지 않음.
3. [검증·리뷰 기준](verification-guide.md)에 따른 통합 증거. 실행은 부모 또는 지정 검증 Agent가 맡을 수 있으며 부모가 결과의 대상·시점·유효성을 확인.
4. 실제 변경·결정·증거를 impl에 기록한 뒤 수용. 의존 TODO는 그 후 시작.
5. 단계 보고 전 [stage 절차](workflow-guide.md#5-보고-전-stage) 수행. 공유 트리에서 index 변경은 부모만 담당.

## 실패·취소·재배정

- 추가 맥락이 필요하면 부모가 계약/brief를 보완한다. 사용자 결정이 필요한 변경은 workflow의 재승인 기준을 따른다.
- timeout·취소·실행 실패 후 같은 쓰기 경로를 재배정하기 전에 이전 Agent와 외부 프로세스의 종료를 확인한다. 상태가 불명확하면 해당 경로를 보류한다.
- 재시도 전에 남은 diff·부분 결과와 실패 원인을 확인한다. 동일한 실패를 해결 근거 없이 반복하지 않는다.
- 설계 변경은 영향받는 worker와 의존 TODO에 전달하고 해당 실행을 중지한다. 영향 없는 승인 작업은 계속할 수 있다.

## 짧은 예

서비스와 테스트가 결합된 T1은 한 worker에게 순차 위임한다. 계약이 고정된 서로 다른 호출부 T2/T3는 T1 수용 뒤 병렬화한다. 두 결과의 쓰기 종료 후 지정 검증자가 공유 checkout에서 통합 테스트를 실행하고 리뷰한다. 부모가 증거를 확인·기록하고 stage한다.
