# 위험도와 단계 분할

위험도는 검증 강도와 단계 분할을 정하는 기준이다. 파일 개수나 문서 분량만으로 판단하지 않는다.

| 위험 | 신호 | 진행 방식 |
|---|---|---|
| 낮음 | 국소 변경, 외부 계약·권한·데이터 영향 없음 | 짧은 plan/impl, 관련 확인과 한 번의 리뷰 |
| 보통 | 여러 계층·API·국소 정책 변경 | 영향받는 계약과 회귀 검증, 필요 시 경계별 단계 |
| 높음 | 데이터 변경/삭제, 권한·테넌트 경계, 동시성·분산 상태, 운영 인프라·대규모 처리 | 실패·호환·복구·동시성까지 검증하고 위험 경계에서 결과 수용 |

작은 변경도 보안·데이터 손실에 영향을 주면 높은 위험일 수 있다. 큰 변경도 반복 문서·테스트 정리라면 파일 수 때문에 전체 검증을 강제하지 않는다.

단계는 독립적으로 확인·되돌릴 수 있는 계약 경계에 둔다. 검증 항목은 [verification-guide.md](verification-guide.md), 추가 문서 필요성은 [record-routing-guide.md](record-routing-guide.md)를 따른다. 위험도 라벨만으로 승인 회차나 문서를 추가하지 않는다.
