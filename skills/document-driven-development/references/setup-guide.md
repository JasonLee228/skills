# DDD 초기 설정

문서 위치나 템플릿이 정해지지 않았을 때만 읽는다. 이미 설정된 프로젝트에서는 setup을 반복하지 않는다.

1. 프로젝트 규칙과 기존 `docs/dev_workflow/`를 확인한다.
2. 기존 템플릿이 있으면 프로젝트 관례를 확인하고, 없으면 이 스킬의 템플릿을 참조한다. 사본을 꼭 만들 필요는 없다.
3. 승인된 문서 작성에 필요한 `plans/active/`, `implementations/active/`와 [로드맵](../templates/roadmap.md) `roadmap.md`만 만든다. 선택 문서 디렉터리는 필요해질 때 생성한다. 과거 작업을 로드맵에 채우는 작업은 사용자가 요청할 때만 한다.
4. API 문서 변경이 필요할 때 해당 문서 위치를 확인한다. 외부 이슈 트래커를 쓰는 프로젝트는 그 연결을 확인한다. 다른 프로젝트의 경로·계정을 추정하지 않는다.

리뷰 도구가 없어도 [기본 검토 기준](verification-guide.md#코드-리뷰)으로 진행할 수 있다. 초기화의 목적으로 스킬 설치, 개인 설정, MCP 인증정보를 임의 변경하지 않는다. 필요한 설정 변경이 기존 승인 범위 밖이면 그 변경만 구체적으로 확인받는다.

실제 생성한 경로와 아직 사용할 수 없는 필수 기능만 현재 작업 기록에 남긴다. 외부 서비스 인증과 쓰기 승인은 별개이며 [workflow](workflow-guide.md#6-외부-업데이트)를 따른다.
