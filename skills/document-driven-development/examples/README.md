# DDD 작성 예시

[설계](12_order_list_status_filter_plan.md)와 [구현 기록](12_order_list_status_filter_impl.md)은 가상의 주문 조회 API 작업을 바탕으로 만든 예시다. 실제 프로젝트의 계약·승인·실행 결과를 증명하지 않는다.

설계에는 계약과 이유를, 구현 기록에는 현재 상태와 증거를 둔다. 공통 절차는 반복하지 않으며, 예시의 경로·명령·시각은 실제 작업에서 확인한 값으로 바꾼다. 위임 여부는 작업마다 정하고 모델·실행 도구는 고정하지 않는다.

로드맵에서는 이 작업이 `#12 | 주문 목록 상태 필터 | 🔵 진행 | plan · impl` 한 행으로 나타난다.
